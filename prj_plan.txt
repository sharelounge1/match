1. 서비스의 큰 목표 & 비즈니스 모델 요약
1.1. 서비스 Vision (큰 목표)

AI 시대에 맞는 새로운 창업 방식—
‘아이디어를 가진 사람’과 ‘기술을 가진 사람’을 지분/수익 공유 방식으로 연결해
누구나 서비스 창업자가 될 수 있는 협업 생태계를 만드는 것.

핵심 가치 제안(Value Proposition)

운영자/마케터/기획자 → 실행력 확보

개발 리소스를 모아 MVP/서비스를 실제로 만들 기회를 제공

개발자 → 사업성, 운영력, 마케팅 역량 확보

개발자 혼자 만들고 버려지는 프로젝트를 운영·마케팅 인력과 결합해 성장시키는 구조

초기 스타트업 실패율 감소

"혼자 만드는 앱" 구조를 넘어 “팀으로 만드는 제품” 구조로 전환

즉,

AI로 ‘개발’이 쉬워진 시대에는 오히려 ‘운영·마케팅·팀빌딩’이 더 중요해진다.
이 서비스는 바로 그 문제를 해결한다.

1.2. 비즈니스 모델 (BM) & 수익 구조
📌 핵심 BM: ‘지분/수익 공유형 매칭’ 플랫폼
📌 수익 구조 (Monetization)
구분	내용
1. 프로젝트 업로드 수수료	운영자/개발자가 프로젝트 등록 시 업로드 비용 과금
2. 미팅 성사 수수료	지원자가 미팅 요청 → 게시자가 수락할 때 결제 발생
3. 표준 계약서 서비스 비용	계약 템플릿 제공/전자서명 비용(선택형)
4. 추후 확장 모델	- 실제 서비스 출시 후 자동 정산 수수료(매출의 x%)
- 광고/노출 우선권 판매
- 커뮤니티 유료 멤버십

→ 핵심은 매칭 기반 반복 매출 구조
→ 나중에는 “협업 기반 창업 생태계”로 확장 가능

2. 서비스 핵심 개념 & 로직 전체 흐름
2.1. 두 가지 핵심 모델
① 아이디어 기반 매칭 (운영자 → 개발자 모델)
운영자/마케터 아이디어 등록  
→ 필요한 팀 체크  
→ 개발자·디자이너·마케터 지원  
→ 미팅  
→ 표준 계약서  
→ 협업 시작

② 서비스 기반 매칭 (개발자 → 운영자 모델)
개발자가 완성/개발중 서비스 등록  
→ 운영/마케팅 인력 모집  
→ 지원  
→ 미팅  
→ 계약  
→ 공동 운영


이 두 모델이 플랫폼의 근간이 된다.

2.2. 핵심 매칭 로직 (Matching Logic)
역할 분류: 4팀 구조

개발팀 (Dev)

운영자 (Biz)

마케팅 (Growth)

디자인 (UI/UX)

역할 체크 방식

게시자: 필요한 역할 1~4개 모두 체크 가능

지원자: 최대 2개 역할 선택 가능 (멀티 포지션 허용)

지분/수익 조건 구조

필수 항목:

지분 %

수익 공유 %

역할에 따른 분배표(자동 생성 가능)

이 항목이 매칭 과정에서 가장 중요한 판단 기준

계약 체결 로직

미팅 성사

상호 조건 협의

플랫폼 내 표준 계약서 자동 생성

전자 서명 → 계약 성립

계약서 서버에 보관 & 양 측 열람 기능

과금 구조

게시글 업로드 시 업로드 비용 → 즉시 결제

미팅 수락 시 미팅 비용 → 즉시 결제

지원자가 신청만 해도 비용은 발생하지 않음(리스크 최소화)

3. 주체별 전체 Flow (UX 관점 상세)
3.1. 운영자/마케터(아이디어 보유자) Flow
회원가입 → 역할 선택 → 아이디어 업로드 → 결제
→ 지원자 확인 → 미팅 요청 수락 → 결제
→ 계약 체결 → 협업 시작

3.2. 개발자 Flow
회원가입 → 포트폴리오 등록 → 만든 서비스 등록(선택)
→ 필요한 운영/마케팅/디자인 역할 체크
→ 운영자/마케터 지원
→ 미팅 → 계약 → 공동 운영

3.3. 지원자(마케터/디자이너) Flow
회원가입 → 역할 선택 → 프로젝트 탐색
→ 지원하기(역할 2개까지 선택)
→ 미팅 신청 → 매칭 → 계약
